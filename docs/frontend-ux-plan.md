# TaskFlow Pro 前端体验升级实施方案

> 目标：把当前「功能完整、但视觉与交互偏通用后台模板」的前端，升级为「让用户用得舒服、愿意留下、能吸引新用户」的产品级界面。
> 范围：仅前端（布局 / 样式 / 设计系统 / 交互 / 引导 / 响应式 / 可访问性），不动后端契约，遵循项目「绝不伪造 API」规则。
> 现状基线（2026-09-17）：TASK-001~096 已交付，前端为 Vue 3 + TypeScript + Vite + Element Plus（按需引入）+ Pinia；标准后台三段式布局。

---

## 0. 背景与目标

当前前端是「能用」的内部系统观感：纯白侧边栏 + 纯白顶栏 + 灰底内容区、Element Plus 默认蓝、单层平铺菜单、卡片式页面、多处「诚实降级」提示直接把后端能力边界暴露给最终用户。功能已闭环，但：

- **没有品牌感**：默认蓝、占位「TF」方块，与任何一个 EP 模板站无差异。
- **信息层级弱**：Dashboard 是 4 个数字卡 + 2 个列表卡 + 一大段「后端没这接口」的告警，用户第一眼抓不到重点。
- **缺少现代 SaaS 的「体感」**：无命令面板、无键盘流、无微动效、无暗色模式、无空状态引导、无新手指引。
- **降级提示太工程化**：把「后端缺聚合端点」这类内部事实直接渲染给终端用户，损害信任感。

升级目标（可量化）：
1. 建立统一 **设计系统（Design Tokens）**，明/暗双主题，全站视觉一致。
2. 重构 **布局与导航**，引入工作区切换、分层菜单、全局命令面板（Cmd/Ctrl+K）。
3. 重做 **核心页面**（首页 / 任务看板 / 任务列表 / 任务详情 / 项目 / 团队）的视觉与交互。
4. 补齐 **空状态、引导、微动效、可访问性、响应式**，让用户「舒服」。
5. 把「诚实降级」从「给用户看的告警」收敛为「优雅的界面留白 + 内部可观测」，不伪造接口但也不吓退用户。

## 1. 市场调研（竞品与趋势）

### 1.1 竞品格局与定位

| 产品 | 定位 | 布局范式 | 视觉/交互标签 | 可借鉴点 |
|---|---|---|---|---|
| **Linear** | 研发团队项目管理 | 左导航 + 内容区，极简 | 暗色美学、键盘优先、Cmd+K、严格对齐、克制配色、微动效 | 命令面板、键盘流、设计令牌、极简聚焦 |
| **Asana** | 跨职能协作 | 左导航 + 顶 Tab + 主内容 | 引导式 onboarding、模板、清晰视觉层级 | 角色化引导、模板 |
| **Notion** | 通用知识/项目 | 顶 Tab + 卡片流、可拼装 | 极简、灵活、块化 | 卡片/块化信息组织、克制 |
| **Trello** | 轻量看板 | 看板优先 | 直观拖拽、低门槛 | 看板拖拽体感 |
| **ClickUp** | 全功能一站式 | 左导航（多层级） | 引导式新手指引、高度可定制 | 引导 tour、可定制视图 |
| **Jira** | 企业研发 | 左导航 + 复杂筛选 | 强大但重、学习曲线高 | （反面教材：避免过重） |
| **飞书多维表格 / Teambition** | 国内协作 | 左导航 + 看板/表格 | 本土化、移动友好 | 移动端友好、本土习惯 |
| **Monday.com** | 可视化工作流 | 色彩化表格/看板 | 强色彩语义、可访问性内置 | 色彩语义化、无障碍 |

### 1.2 主流布局范式（来自行业综述）

1. **左导航 + 主内容区**：复杂功能场景（Jira/Asana/Linear），适合本项目（多模块：任务/项目/团队/权限）。
2. **顶 Tab + 卡片流**：轻量场景（Trello/Notion），适合看板/项目内视图切换。
3. **沉浸式全屏**：创意/画布类，本项目暂不需要。

结论：本项目应**保留「左导航 + 主内容」主骨架**（与现有结构兼容、迁移成本低），在局部引入顶 Tab（项目/任务内视图切换）与看板流。

### 1.3 2025 视觉与交互趋势（提炼）

- **极简 + 清晰信息层级**：关键指标置顶加粗，F/Z 阅读动线，留白即设计。
- **暗色模式成为默认期待**：长时间使用的协作工具尤其需要。
- **设计令牌（Design Tokens）驱动一致性**：颜色/间距/圆角/阴影统一变量，跨端一致（Linear 用 LCH 统一感知亮度）。
- **Bento 网格**：把异构信息（指标/列表/图表）装进规整分区的卡片矩阵，Dashboard 首选。
- **有意义的微交互**：hover、状态切换、数据刷新用克制动效表达「活的」，而非装饰。
- **命令面板（Cmd+K）+ 键盘优先**：专业用户效率倍增（Linear/Notion 标配）。
- **渐进式披露（Progressive Disclosure）**：先给概要，按需展开细节，避免信息过载。
- **可访问性（WCAG 2.2）内置**：对比度、键盘可达、ARIA、避免闪烁。
- **移动优先 / 响应式重排**：小屏用卡片视图、可折叠、手势，而非简单缩放。
- **空状态即引导**：空列表不是「暂无数据」四个字，而是带插画 + 下一步动作。

### 1.4 关键借鉴点提炼（落到本项目）

1. **设计令牌 + 双主题**（最高优先级基建）。
2. **Cmd+K 命令面板 + 键盘快捷键**（效率与「高级感」的强信号）。
3. **Bento Dashboard**（首屏体验核心）。
4. **分层侧边栏 + 工作区/租户切换器**（契合多租户 SaaS 定位）。
5. **优雅空状态 + 新手指引 tour**（降低留存门槛）。
6. **克制配色 + 语义色系统 + 微动效**（品牌感与体感）。
7. **移动端响应式重排**（拓客与留存）。

## 2. 设计考察：现状与差距

### 2.1 现状快照（基于代码实际）

- **技术栈**：Vue 3.5 + TS + Vite 7 + Element Plus 2.14（按需引入，命令式 API 需手动补样式）+ Pinia 3 + vue-router 4。无 UI 测试框架之外的设计系统。
- **布局**：`el-container` 三段式 —— 侧边栏 220/64px、顶栏 56px、内容区 `padding:16px`、灰底 `#f5f7fa`。
- **侧边栏**：纯白、单层 7 项平铺菜单、品牌区「TF」蓝方块 + 标题；无分组、无工作区切换、无折叠菜单、`<992px` 才自动收起。
- **顶栏**：仅折叠按钮 + 通知铃铛 + 用户菜单，无搜索/命令入口、无面包屑外的上下文。
- **配色**：沿用 EP 默认主色 `#409eff`，无任何 token 覆写、**无暗色模式**、无品牌专属色。
- **Dashboard**：4 个 `el-statistic` 数字卡 + 2 个列表卡 + 一段 `el-alert` 解释「后端无聚合端点」——首屏被工程化说明占据。
- **任务看板**：5 态列 + HTML5 拖拽流转，卡片基础；无列内计数可视化、无优先级色彩条、无筛选条。
- **降级提示**：Dashboard / 项目列表 / 通知列表 / 任务详情多处 `el-alert`「诚实降级」，面向终端用户暴露后端能力边界。
- **交互**：仅路由切换淡入；无命令面板、无快捷键、无骨架屏（用 `el-skeleton` 但无统一加载态）、无 toast 体系规范。
- **可访问性/响应式**：语义基础，未做对比度/ARIA/键盘流专项；响应式仅侧边栏收起。

### 2.2 差距分析表

| 维度 | 现状 | 标杆（Linear/Asana/Monday） | 差距 | 优先级 |
|---|---|---|---|---|
| 设计系统 | 无 token，EP 默认 | 完整令牌 + 双主题 | 高 | P0 |
| 品牌感 | 默认蓝 + 占位 logo | 专属色 + 字体 + 标识 | 高 | P0 |
| 布局/导航 | 单层平铺菜单 | 分层 + 工作区切换 + 命令面板 | 高 | P0 |
| 首页体验 | 数字卡 + 工程告警 | Bento + 洞察 + 引导 | 高 | P1 |
| 任务体验 | 基础看板/列表 | 视图切换 + 筛选 + 键盘 + 色彩语义 | 中 | P1 |
| 空状态/引导 | 默认 empty + 告警 | 插画 + 下一步 | 中 | P1 |
| 微动效/反馈 | 仅路由淡入 | 克制微交互 + 骨架屏 | 中 | P2 |
| 暗色模式 | 无 | 默认期待 | 中 | P1 |
| 可访问性 | 基础 | WCAG 2.2 | 中 | P2 |
| 响应式 | 仅收起侧栏 | 移动端重排 + 手势 | 中 | P1 |
| 降级呈现 | 用户可见告警 | 优雅留白 + 内部可观测 | 中 | P1 |

### 2.3 关键痛点（一句话）

> 功能闭环但「不像一个产品」：没有设计语言、没有首屏焦点、没有效率装备（命令面板/快捷键）、把内部限制甩给用户看。

## 3. 设计方向（Design Direction）

### 3.1 体验原则

- **聚焦（One thing at a time）**：每屏一个主任务，信息层级先总后分。
- **克制即高级**：配色少而准，动效少而有意义，不堆装饰。
- **效率装备**：键盘优先 + 命令面板，让重度用户飞起来。
- **诚实但优雅**：后端没有的能力，用「界面留白 + 内部埋点」表达，不弹工程告警。
- **一致**：所有间距/圆角/阴影/色彩来自同一组 token。

### 3.2 设计系统（Design Tokens）

覆盖 `frontend/src/assets/styles/tokens.css`（CSS 变量），并覆写 Element Plus 同名变量实现主题统一。

**色彩**
- 品牌主色（建议从默认蓝升级为更具辨识度的 **靛蓝 Indigo `#4F46E5`** 或 **青蓝 Teal `#0EA5E9`**；本文以 Indigo 为例，落地时由品牌决策定稿）—— 主色、悬停、激活、浅底四档。
- 语义色：成功 `#16A34A` / 警告 `#D97706` / 危险 `#DC2626` / 信息 `#2563EB`（与状态/优先级映射）。
- 中性阶：`gray-50..900` 11 档，用于背景/边框/文本。
- 表面层级：背景、卡片、弹出层三档明度，构建纵深。

**字体**
- 中文：`PingFang SC` / `Microsoft YaHei`；西文/数字：`Inter`（引入 woff2，提升数字与英文观感）。
- 字号阶梯：12 / 13 / 14（基）/ 16 / 18 / 20 / 24 / 30 / 36，行高 1.5（正文）~1.2（标题）。

**间距（8px 基准网格）**
- `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`，全站只用这组值，杜绝魔法数。

**圆角**
- `sm 6 / md 8 / lg 12 / xl 16`，卡片用 `lg`，按钮/标签用 `sm/md`。

**阴影 / 描边**
- 三档：低（卡片静止）、中（悬浮）、高（弹出/命令面板）；描边统一 `1px var(--tf-border)`。

**层级（z-index）**
- 统一令牌：基准 / 吸顶 / 抽屉 / 弹窗 / 命令面板 / Toast。

### 3.3 双主题（明 / 暗）

- 用 `data-theme="light|dark"` 挂在 `<html>`，所有 token 出两套值；覆写 `--el-color-primary` 等 EP 变量，使 EP 组件自动跟随。
- 暗色：深灰表面（`#0F1115` 系）、低饱和强调、降低对比刺激，长时间使用护眼。
- 主题持久化到 `localStorage`，跟随用户偏好。

### 3.4 布局骨架

```
┌────────────┬──────────────────────────────────────────────┐
│            │  顶栏：命令搜索 / 通知 / 用户 / 主题切换        │
│  侧边栏     ├──────────────────────────────────────────────┤
│  - 工作区   │  面包屑 / 视图 Tab（列表·看板·时间线）          │
│    切换器   ├──────────────────────────────────────────────┤
│  - 主导航   │                                              │
│    (分组)   │           工作区（Bento / 看板 / 列表）        │
│  - 设置     │                                              │
│  - 主题     │                                              │
└────────────┴──────────────────────────────────────────────┘
```

- **侧边栏分层**：顶部「工作区/租户切换器」（契合多租户），中部按分组组织主导航（工作 / 协作 / 管理），底部用户·主题·设置。
- **顶栏命令搜索**：点击或 `Cmd/Ctrl+K` 唤起全局命令面板（跳转 / 新建任务 / 切换项目 / 主题）。
- **视图 Tab**：项目、任务内提供 列表 / 看板 /（未来）时间线 视图切换，保留顶 Tab 范式。
- **命令面板**：独立浮层（高 z-index、毛玻璃背景），键盘可达，输入即筛。

## 4. 核心页面改造路线

### 4.1 登录 / 注册（AuthLayout）
- 左右分栏或居中卡片 + 品牌色渐变侧/顶，弱化「表单 Site」，强化「产品感」。
- 输入框聚焦态、提交 loading、错误态统一；支持「记住我 / 忘记密码」占位（不伪造接口，仅 UI）。
- 顶部品牌标识 + 一句话价值主张（如「让团队任务一目了然」）。

### 4.2 首页 Dashboard（重做核心）
- **Bento 网格**：左大右小分区。
  - 主卡：我的待办概览（按状态分组的迷你进度环 / 条形）。
  - 卡组：近期截止、逾期提醒、本周完成、未读通知（语义色高亮紧急项）。
  - 卡组：我的最近项目 / 团队（可点击进入）。
- **不弹「后端没接口」告警**：用已能拿到的数据（我的任务按项目分别拉取后在客户端聚合）呈现；若确无跨项目端点，设计为「按项目浏览」的优雅入口，而非错误说明。
- **空状态引导**：无任何数据时，整页插画 + 「创建第一个项目 / 邀请成员」CTA。

### 4.3 任务（列表 / 看板 / 详情 / 创建）
- **看板**：列头带状态色条 + 计数胶囊；卡片加优先级色边、负责人头像、截止日；顶部筛选条（负责人/优先级/标签）+ 视图切换；拖拽落点高亮（已有基础，补视觉）。
- **列表**：表格化 + 行内快捷操作（完成/流转/指派） + 列排序 + 多选批量；密度可调（紧凑/舒适）。
- **详情**：两栏（主区描述/活动流，侧栏属性）；活动流替代当前「操作日志占位」——若无后端端点则显示「暂无动态」优雅态，不弹告警。
- **创建**：抽屉式（`el-drawer`）快速建单，减少跳转；字段聚焦顺序优化。

### 4.4 项目 / 团队
- 项目列表：卡片网格 + 搜索/筛选（客户端降级保持，但 UI 收敛为正常筛选控件，不告警）。
- 项目详情：Tab（概览/任务看板/任务列表/设置）统一视图切换范式。
- 团队：成员网格 + 角色标签 + 邀请入口（UI）。

### 4.5 通知 / 权限 / 设置
- 通知：已读/未读分区、批量已读、类型图标；降级信息收敛为页面说明小字。
- 权限：矩阵可视化（角色 × 权限），已具备，补间距/对齐/色彩使其「专业」。
- 设置：新增「外观（明/暗/跟随系统）」「快捷键」「通知偏好」等前端可控项。

## 5. 组件与模式规范

- **统一加载态**：用 `tf-skeleton` 包裹区块；EP `v-loading` 保留但统一蒙层样式。
- **Toast/Message**：统一用语与配色（成功绿、错误红、信息蓝），避免散落 `ElMessage.success`。
- **空状态组件 `EmptyState.vue`**：插画（内联 SVG，不引外部图）+ 标题 + 描述 + 主/次动作，替换默认 `el-empty` 与告警。
- **命令面板 `CommandPalette.vue`**：全局单例，注册命令（路由跳转、新建、主题、快捷键帮助）。
- **快捷键层**：`keymap` 组合（新建任务 `C`、搜索 `Cmd+K`、帮助 `?`），页面内提供 `?` 帮助浮层。
- **微动效**：路由切换、卡片悬浮、面板滑入、数字滚动（KPI）、状态变更高亮，全部走 token 化 CSS 过渡，禁用长耗时动效。
- **表单**：统一 label/校验/错误态样式；聚焦环用品牌色。

## 6. 可访问性与响应式

- **可访问性（WCAG 2.2 AA）**：对比度达标（双主题均校验）、全功能键盘可达、焦点环可见、`aria-label` 补菜单/图标按钮、减少 `aria-live` 用于通知、避免自动闪烁。
- **响应式重排**：
  - `≥1280`：完整三段式。
  - `992~1279`：侧栏可折叠。
  - `<992`：侧栏抽屉化（overlay），顶栏保留核心；看板横向滚动、列表转卡片、Dashboard Bento 单列堆叠。
  - 触摸目标 ≥ 44px，手势友好。

## 7. 分阶段实施计划（与 TASK 体系衔接）

> 建议作为**独立阶段**排期（接续当前前沿，建议编号 **TASK-128 起**，独立于企业化 Phase 20~23 的 097~127，避免打断后端主线；可并行推进）。
> 严格遵循既有约束：
> - Element Plus 按需引入 → **命令式 `ElXxx` 必须在 `main.ts` 补样式行**；
> - 构建须挂 `CODEBUDDY_SAFE_DELETE_ENABLED=0`；
> - 新增 TASK 须登记 `TASKS.md`（新 Phase 插在「TASK 执行规则」前）+ `PROGRESS.md` 的 `## Next`；
> - **绝不伪造后端 API**：降级用优雅 UI，不弹工程告警；

## 8. 风险与注意事项

- **不破坏现有契约**：所有接口调用不变；聚合类 Dashboard 若确需后端端点，应另开**后端 TASK**（如 `/me/overview`），前端方案以「客户端聚合已有数据」为 interim，不伪造。
- **EP 按需引入陷阱**：新增任何命令式 `ElXxx` 必须同步 `main.ts` 补样式，否则样式缺失且无报错（已在 `FRONTEND_API_MAPPING` 记录）。
- **构建守卫**：`build` 与大量文件操作须 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，否则沙箱批量删除守卫会拦截。
- **文档护栏**：任何改动若触及 README/QUALITY/TASKS/PROGRESS 的数字声明，须同步并重跑 `check_docs.py`（RC 0）。
- **主题覆盖的副作用**：覆写 EP 变量后需回归常用组件（表格/表单/弹窗/抽屉）双主题外观。
- **性能**：暗色与微动效用 CSS 变量与 `transform/opacity`，避免触发重排；命令面板数据惰性加载。
