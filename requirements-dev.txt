# TaskFlow Pro — 开发与 CI 专用依赖（TASK-061）
#
# 为什么单独一个文件，而不是塞进 requirements.txt：
#   requirements.txt 被 Dockerfile 用于**生产镜像**（`COPY requirements.txt` +
#   `pip install -r`）。把 lint 工具装进生产镜像既是纯死重量（ruff 约 10MB），
#   也让「运行时依赖」和「开发工具」混在一起，无法单独审计生产镜像里装了什么。
#   本地开发与 CI 装本文件：`pip install -r requirements-dev.txt`。
#
# 已知妥协（有意保留，不做无关改动）：pytest / httpx / PyYAML 等测试依赖历史上
# 就在 requirements.txt 里（因而也进了生产镜像）。本 TASK 不搬动它们——那是独立的
# 依赖整理工作，不属于「加 CI」的范围（项目规则 §5）。见 DECISIONS 043。

-r requirements.txt

# Lint：CI 的 lint job 使用，本地设 pre-commit 前也可手动跑 `ruff check .`。
# 版本固定以保证 CI 可复现（规则集在 pyproject.toml 里同样显式钉死）。
# 注意：PyPI 清华镜像没有 ruff，本机安装需指定官方源——见 docs/DEPLOYMENT.md。
ruff==0.16.7

# 因此本依赖仅用于本地 `pytest --cov`。版本固定以让「本地测出的数」可比对。
# 与 ruff 同样的问题：清华镜像缺 pytest-cov，本机安装需指定官方源（见 docs/DEPLOYMENT.md）。
pytest-cov==7.1.0
